Apex Terminal

Split-pane terminals in a browser tab, with broadcast, keep-alive and a connection history. Python 3.11 and nothing else — a terminal is what you reach for when a machine is already in a bad way, and “install this first” is the wrong answer at that moment.

Panes and splits

The layout is a binary tree, so closing a pane collapses its parent back into its sibling instead of leaving a hole. Drag any divider to re-balance.

Broadcast, and send to all

Broadcast sends every keystroke to every pane — tmux's synchronize-panes. The chrome turns amber and stays amber, because forgetting it is on is how you run a command on nine machines you meant to run on one.

Send beside it is the deliberate one-shot: type a line, press Enter, it lands in every pane.

Sessions outlive their socket

Close the tab, lose wifi, suspend the laptop — the command keeps running. Reopening replays the scrollback and carries on. The Running tab attaches a session no pane is currently showing.

Keep-alive, at two levels

The server pings every idle socket every 20 seconds, which stops a proxy or a power manager deciding the browser link is dead.

Anti-idle is the other half: it writes a NUL byte into any session quiet for the interval you pick, so the far end sees traffic and does not time you out. Shells discard it. It is off by default and the pane says so while it is on — it is still a write into somebody else's shell.

Inside ApexBuild, and the trust boundary

Started by the suite, this takes the ApexBuild sign-on, so it knows who is using it without asking for a second password. Run on its own it behaves exactly as it always has.

That is identity, not a lock. This app binds loopback and has no authentication of its own: anything that can reach the port can open a shell as you. The WebSocket checks Origin, because browsers do not apply CORS to WebSocket handshakes and without it any page on the internet could open one. Keep it on 127.0.0.1; if it has to go further, put something that authenticates in front.
