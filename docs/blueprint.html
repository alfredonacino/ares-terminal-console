Architecture blueprint

ARES Terminal Console

How the terminal is built and run. One small Python server, standard library only, owns the shells and carries their bytes to a window over WebSocket. Sessions belong to the server, not the window, so they survive a closed tab. Seven read-only server tools ride the SSH login already typed into a pane, and nothing reaches Claude or OSV.dev until the operator has seen it and pressed Send.

A-01

System context

Who uses it, what it runs on, and what it talks to.

No dependencies

The server is Python standard library only. claude-agent-sdk is optional and imported lazily; without it, only the ask bar is missing.

One codebase, three hosts

Desktop app, Docker image and ApexBuild module run the same server. The host decides where it listens, where data lives and how the window is shown.

No API key in the app

The assistant runs on the operator's installed Claude Code, signed in with their Claude subscription.

A-02

Software components

The modules under app/, and which imports which.

Threads, not async

One thread per HTTP request and a reader/writer pair per attached WebSocket. Each session has its own reader thread.

Vendored, not imported

sso.py is copied from ApexBuild so the module still runs on its own. xterm.js is vendored under static/vendor/, with no CDN.

Same diagnosis

The AI prompts in insight/service.py are ARES Ultimate Console's, word for word, so both products reach the same conclusions.

A-03

A keystroke and its output

The PTY belongs to the server. A WebSocket only attaches to it.

Keep-alive

The server pings every idle socket every 20 s, so a proxy or power manager does not decide the connection is dead. Frames over 4 MB are refused.

Anti-idle

Off by default. When set, a NUL byte is written to a session quiet for the chosen interval, so the far end sees traffic. Shells discard it.

Broadcast

Done in the UI: the same input is sent to every pane of the tab on screen. The server sees ordinary input.

A-04

Server tools over the pane's own login

OpenSSH connection sharing. Nothing installed on the server, nothing changed.

Left alone

A command that already sets ControlMaster, ControlPath or -S keeps its own choice. %C hashes host, port and user, so two servers never share a master.

Typed ssh

Local panes get an ssh wrapper on PATH that adds the same sharing for interactive logins only. Git, rsync and scripts get plain ssh.

Windows

Windows' OpenSSH cannot multiplex, so nothing is added there and the tools need a key or an agent.

Local panes

◈ system runs the same scripts in the local shell. Its Stop refuses the app's own process.

A-05

Consent before anything leaves

The AI analyses and the vulnerability lookup.

The ask bar

The agent has no tools and no permission to use any. INSERT puts the command at the prompt without a newline; the operator presses Enter. Broadcast is ignored.

Subscription

Asks go through the operator's Claude Code login. An ANTHROPIC_API_KEY is hidden from the assistant unless ARES_ASK_AUTH=api-key.

Cost ledger

Questions, tokens, model and cost are kept in agent-costs.json. Answers are not stored there.

A-07

Build and release

PyInstaller does not cross-compile, so each platform builds on its own kind of machine.

Linux data

~/.local/share/ares-terminal-console

macOS data

~/Library/Application Support/ARES Terminal Console

Windows data

%APPDATA%\ARES Terminal Console

Docker data

/data; shells run as the unprivileged user ares.

A-08

Interfaces

Every HTTP route, and the files the server keeps. Where a token is in use, every route needs it except /api/health.

Sessions

  • GET/api/sessions
  • POST/api/sessions {command, cwd, cols, rows}
  • POST/api/sessions/<id>/kill
  • GET/api/sessions/<id>/where
  • WS/ws?session=<id>

History & commands

  • GET/api/history
  • POST/api/history/save · forget · clear
  • POST/api/sessions/<id>/command {command, how}
  • GET/api/commands ?session=&connection=&q=
  • POST/api/commands/clear

Servers & tools

  • GET/api/connections · POST/forget
  • GET/api/servers · /api/servers/<id>
  • POST/api/servers/<id>/forget
  • */api/insight/<session>/identity · health · perf
  • */api/insight/<session>/logs · packages · vulns · history
  • POST…/perf|logs/ai/preview · …/ai · …/vulns/lookup

Assistant

  • GET/api/agent/state
  • POST/api/agent/ask
  • GET/api/agent/costs
  • POST/api/agent/costs/clear

Other

  • GET/api/health (no token)
  • GET/api/colors (ls legend)
  • GET/ the UI (static/)
  • apexmod info · check · run --host --port
